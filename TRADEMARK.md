# ClipRiva name and logo policy

- **Policy owner:** Sealdot404
- **Status:** project policy draft for the first public release; not a statement that any mark is
  registered in a particular jurisdiction.

The Apache-2.0 license applies to the repository's code and documentation. It does not grant a
license to use the ClipRiva name, logos, or other project branding except for reasonable factual
reference to the origin of the software.

## Permitted factual use

You may use the name “ClipRiva” to truthfully describe an unmodified copy of the project, discuss
compatibility, link to the project, or provide factual commentary, review, documentation, or news
coverage. Do not imply Sealdot404 endorses, sponsors, certifies, or supports your work unless you
have prior written permission.

## Forks and modified distributions

If you distribute a modified version or a fork:

- use a distinct product name and a distinct application/bundle name;
- replace the ClipRiva logos and app icons;
- do not name the product “ClipRiva Official”, “Official ClipRiva”, or any confusingly similar name;
- clearly state that it is an unofficial fork and identify the source revision when practical; and
- do not imply the fork has the same privacy, security, signing, support, or compatibility status as
  an official ClipRiva release.

You may say “based on ClipRiva” or “a fork of ClipRiva” in a factual description.

## Official builds

An official ClipRiva build is one that Sealdot404 has built or explicitly authorized, published from
an identified official channel, and—when release documentation requires it—signed and notarized.
Third-party, local, unsigned, or forked builds are not official builds.

## Screenshots and media

Reasonable use of unmodified screenshots for commentary, documentation, reviews, or news reporting
is permitted when the source is identified and no endorsement is implied. Do not use screenshots or
logos in a way that misrepresents the product, distributes private clipboard content, or suggests an
official relationship that does not exist.

## Asset provenance

The current application icons, root assets, and documentation screenshots are represented by
Sealdot404 as self-owned, Codex-assisted, and human-reviewed. Every new asset must receive the same
provenance review before it is published. Project maintainers should preserve any available creation
records and remove or replace an asset if a third-party-rights concern is substantiated.

## Contact

Questions about security issues must follow [SECURITY.md](SECURITY.md). General project questions
should use the repository's public discussion or issue channels once available; do not post sensitive
information publicly.
