# ClipRiva v1.5 首次使用与常见问题

## 三分钟开始使用

1. 打开 ClipRiva，复制两段普通文本，确认它们出现在 History。检测为高置信度敏感内容时，ClipRiva 会按当前策略在写入前丢弃本条；Strict 模式还会暂停后续采集。
2. 按默认快捷键 `Command + Shift + Space` 打开 Quick Paste。用方向键选择，按 Enter 恢复到剪贴板；直接粘贴模式需要单独开启并授权辅助功能。
3. 在 History 选择一条记录，可置顶或添加标签。标签最多 8 个、每个最多 24 个可见字符，只保存在本机数据库中。
4. 用 History 的类型、来源应用、标签和最近使用筛选缩小范围。命令行内容会在有明确命令结构时显示为 Command；普通句子仍按 Text 处理。

## 在两台 Mac 之间发送一条文本

Local Link 当前是默认关闭的 Release Candidate。它不是历史同步，也没有云中继、离线正文队列或自动重试。

1. 在两台 Mac 的 Settings 中分别开启 Local Link，并确认两台设备位于同一局域网。
2. 从 Nearby devices 选择另一台 Mac。逐项核对两端相同的安全码和双方身份指纹，再在两端确认。
3. 选择信任期限：仅本次会话、30 天或持续信任到手动撤销。
4. 在 History 选择一条支持的文本记录，打开 Local Link 并明确发送。
5. 接收端在 60 秒内选择 Copy、Save 或 Reject。Copy 只写入系统剪贴板；Save 只写入本机 History；超时或拒绝不会保存正文。

如果设备显示 Needs re-pairing，请让另一台 Mac 保持 ClipRiva 和 Local Link 开启，再从当前 Nearby devices 重新选择并核对安全码。旧的稳定设备标识不会被当作新的发现候选。

## 常见问题

### 为什么 Quick Paste 的第一项变了？

无搜索词时按最近活动排序；刚复制或恢复的条目优先。固定条目仍会在有限结果窗口中保留可见位置，但不会覆盖最近活动顺序。输入搜索词后改为相关性优先。

### 标签会发送到另一台 Mac 或诊断文件吗？

不会。标签是新的本机存储数据类型，只用于本机组织和搜索；Local Link payload、传输状态和诊断均不包含标签或正文。永久删除一条 History 记录时，其标签随记录级联删除。

### 为什么某段内容没有被识别为 Command？

分类器故意保守，只识别已知命令入口、shell 提示符、明确可执行路径或 shell 语法，避免把自然语言误判为可执行命令。URL、代码和颜色等更明确类型仍优先。

### 为什么 Local Link 找不到另一台 Mac？

确认两台 Mac 位于同一 Wi-Fi、另一端 ClipRiva 正在运行、两端都已开启 Local Link，并检查 macOS 本地网络权限、防火墙、VPN 或 AP 隔离。然后选择 Scan again。当前候选在真实双 Mac 的换网、睡眠/唤醒和签名安装矩阵完成前仍是公开发布 No-Go。

### 如何清理或彻底重置本机数据？

History 清理会先显示影响预览，默认保留置顶内容，并把可恢复记录移入本机回收站。应用数据位于 `~/Library/Application Support/com.clipriva.desktop/`；手动删除前必须退出 ClipRiva，且删除不可恢复。Local Link 身份另存于 macOS Keychain；若也要重置身份，请使用 Local Link 安全设置中的 Reset identity。
