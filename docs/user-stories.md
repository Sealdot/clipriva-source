# ClipRiva 0.4 用户故事

## 文档目的

本文将 `0.4` ClipRiva 的目标能力，以用户故事和验收条件描述出来。它服务于
日用 Beta 验证和后续缺陷归类，不是未来平台功能的需求清单。

**0.4 修订方向（可靠找回与安全清理）：** 保留 Quick Paste 的高频路径，同时把结果状态、
本地回收站、精确重复分组、可执行的隐私原因与可选本地诊断补成完整闭环。所有清理操作先
预览再执行；不包含账户、跨设备同步、云端 AI、语义/模糊去重或图片指纹。完整实现范围和
测试用例见 [0.4-revised-acceptance.md](0.4-revised-acceptance.md)。

**产品定位：** ClipRiva 是面向 macOS 的开源、本地优先剪贴板工具，帮助用户更快、更可控地
找回和复用复制内容；Core 无需账户、网络或 AI。

## 范围与角色

### 主要用户

| 角色 | 特征 | 主要诉求 |
| --- | --- | --- |
| 键盘重度用户 | 频繁在编辑器、终端、浏览器和文档应用间切换。 | 不离开当前工作流就能找回并复用复制内容。 |
| 隐私敏感的开发者 | 可能复制令牌、配置、代码与客户信息。 | 明确控制哪些内容留在本机、哪些应用不应被捕获。 |
| 本地优先工具使用者 | 不希望为基础效率工具注册账户或上传剪贴板。 | 离线、透明、可审计且可长期使用。 |

### 当前范围

- **ClipRiva Core：** 默认启用、离线可用、完整的日用剪贴板产品。
- **ClipRiva Labs：** 默认关闭的本地实验能力；启用后才显示摘要、实验检索和文本 Actions。
- **不在当前范围：** Windows、Linux、账户、跨设备同步、云端 AI、MCP、Agent、公开插件 SDK。

## Core 用户故事

### US-C00：完成首次找回与复用

作为一名首次使用者，我想在安装后快速找回上一段复制内容，
从而在理解隐私说明后马上感受到 ClipRiva 的实际价值。

验收条件：

- 完成首次隐私说明后，只提示一个核心动作：“复制两条内容，然后按 Quick Paste 快捷键找回前一条”。
- 用户复制第二条内容后，Quick Paste 能展示并恢复前一条内容。
- 首次恢复成功后，教学提示自动结束，后续不重复打扰。
- 快捷键冲突时提供替代预设，不要求用户自行排查系统设置。
- 首次价值路径不要求打开 History、进入 Settings 或理解 Labs。

关联验证：`V-00`、`Q-01`。

### US-C01：理解产品的本地与隐私边界

作为一名首次使用者，我想在开始前知道 ClipRiva 会保存什么、保存在哪里、是否需要账户或网络，
从而决定是否将其作为日用工具。

验收条件：

- 首次启动以不超过三个要点说明本地存储、无账户/网络和敏感内容保护；确认后直接进入 `US-C00`。
- 首次启动说明以模态方式呈现，焦点先进入“Start using ClipRiva”；Tab 不会进入被遮罩的主界面。
- 用户确认后可继续使用，并可在 Settings 中再次查看和调整相关规则。
- 打开 Settings 后焦点进入对话框；Tab/Shift+Tab 在对话框内循环，Escape 关闭后焦点返回触发入口。
- 文档说明本地数据目录及手动清除数据会删除历史和设置。

关联验证：`P-01`、`P-04`、`P-07`。

### US-C02：自动保留常用复制内容

作为一名日常办公或开发用户，我想让 ClipRiva 在后台保留我复制的内容，
从而不必因为新的复制操作而丢失先前内容。

验收条件：

- 在应用运行期间，文本和 PNG 图片会被本地捕获。
- 捕获尽力记录来源应用；无法取得来源时仍可保存内容。
- 完全相同的文本、代码、URL、颜色和文件引用会保留为独立版本，并按存储层给出的精确分组
  折叠显示；默认仅显示最新版本。
- 精确分组不会忽略大小写、空格或换行差异，不使用语义/模糊相似度，也不使用图片指纹。
- 重启应用后，历史和精确分组仍可被读取。
关联验证：`C-01`、`C-02`、`C-05`、`C-06`。

### US-C03：保留格式与文件引用

作为需要复用文档片段或 Finder 文件的用户，我想找回富文本和文件引用，
从而不只限于纯文本剪贴板历史。

验收条件：

- RTF/HTML 与对应纯文本会作为富文本记录保存，并可写回 macOS 剪贴板。
- Finder 的单个或多个文件复制会保存为本地文件引用，而不是读取或复制文件内容。
- 恢复文件记录后，可在 Finder 等支持文件粘贴的应用中复用这些引用。

关联验证：`C-03`、`C-04`。

### US-C04：快速搜索并恢复历史内容

作为频繁切换应用的键盘用户，我想通过全局快捷键搜索历史并恢复内容，
从而避免打开主窗口和反复重新复制。

验收条件：

- 用户可用全局 Quick Paste 快捷键打开默认的高频搜索面板，并可在 Settings 选择快捷键预设。
- 面板支持关键词过滤、上下键导航、Enter 选择和 Escape 关闭。
- Quick Paste 打开后搜索框自动聚焦，默认连续显示 7–9 条结果；Space 仅临时预览当前项，不常驻详情栏。
- Restore 成功明确显示“已恢复到剪贴板”，并提示用户回到目标应用按 Command-V。
- Direct Paste 的结果明确区分“已向目标应用发送粘贴”（不承诺目标应用已接收）与“未能发送，
  内容仍在剪贴板”；后者可重试并仅显示权限、焦点或兼容性等宽泛原因。
- 主窗口搜索使用本地 FTS，不依赖网络或外部模型；Command-K 可将焦点移入搜索框。
- 主窗口历史列表支持上下键选择和 Enter 恢复当前选中记录，不会劫持正在编辑输入框的方向键。

关联验证：`C-01`、`Q-01`、`Q-02`、`Q-03`。

### US-C05：在明确授权后直接粘贴

作为追求更快操作的用户，我想在明确开启后让 ClipRiva 直接粘贴到原应用，
同时不希望系统权限不足时产生错误输入或丢失内容。

验收条件：

- 直接粘贴默认关闭；开启时明确解释 macOS 辅助功能权限的用途。
- 已授予权限时，ClipRiva 恢复内容、返回原应用并发送 Command-V；界面只承诺已发送该命令，
  不把目标应用是否接收表述为成功。
- 权限未授予、被拒绝或后来撤销时，不合成键盘输入；内容仍恢复到剪贴板，并提示用户手动粘贴。
- 原应用已退出或无法激活时，不向错误目标应用粘贴。

关联验证：`Q-04`、`Q-05`、`Q-06`、`Q-07`。

### US-C06：整理和长期保留重要内容

作为会反复复用固定片段的用户，我想置顶、删除或清理历史，
从而让常用内容可访问，同时控制本地历史的大小。

验收条件：

- 用户可置顶或取消置顶单条记录；置顶记录在常规清理中保留。
- 单条、批量、清除未置顶和保留策略清理使用同一预览：显示影响数量、置顶跳过数量、规则、
  不含内容的代表项和本地回收窗口；默认焦点为 Cancel。
- 确认后条目进入本地 Recycle Bin，而非直接永久删除。默认可恢复期是“7 天与原剩余保留期
  中较短者”；Strict 模式缩短为最多 1 天。
- 恢复复用原始记录，不改变最初捕获时间、来源、置顶状态或精确分组，仅增加恢复时间；恢复后
  不自动置顶或移动到列表顶部。
- 置顶条目默认跳过；若用户在已选条目中包含置顶项，必须先看到跳过提示，再显式纳入后重新确认。
- Recycle Bin 中的永久删除和清空操作有独立二次确认；媒体仅在没有任何引用后才清理。
- 用户可设置保留天数与未置顶记录数量上限，保存规则后或从 History 菜单进入“Review retention
  cleanup”时，可预览对应的保留策略影响。
- 无历史、无搜索结果和无置顶记录分别提供相应的下一步提示，避免把空状态误解为数据丢失。

关联验证：`C-06`、`C-07`、`C-08`。

### US-C07：阻止不应保存的内容

作为隐私敏感用户，我想暂停捕获、排除指定应用，并在高置信敏感内容出现时停止记录，
从而减少剪贴板历史带来的风险。

验收条件：

- 用户可手动暂停和恢复全部捕获；暂停不会删除已有历史。
- Capture 状态会显示暂停原因（手动暂停或检测到敏感内容），并提供直接恢复操作。
- 用户可设置应用排除列表；来自该应用的内容在写入前丢弃。
- 默认保护检测到高置信私钥或访问令牌特征时，内容不写入历史，但 Capture 继续运行。
- Strict 保护检测到相同特征时，内容不写入历史，Capture 自动暂停并说明原因与 Resume 操作。
- 隐私页将最近原因归为保护规则、排除应用、手动暂停或系统格式限制，并提供“查看规则”、
  “管理 Excluded apps”或“Resume Capture”等对应入口，不展示被拒绝内容。
- Strict 模式恢复 Capture 前要求明确确认；恢复后 Strict 仍保持启用。
- 该类被拒绝内容不会进入 Labs 的派生摘要或检索数据。

关联验证：`P-02`、`P-03`。

### US-C09：选择性查看本地可靠性诊断

作为一名希望排查找回体验的用户，我想自主开启仅在本机保存的汇总诊断，
从而了解找回、直接粘贴、回收站恢复和重复组展开是否可靠，而不泄露剪贴板内容。

验收条件：

- Diagnostics 默认关闭，位于 Privacy 的二级入口；开启后只记录固定事件/结果、日期桶和应用版本。
- 页面显示首次找回完成率、Direct Paste 降级率、回收站恢复数、重复组展开数和关键错误类别。
- 记录、清空和导出不包含内容、哈希、文件名、路径、来源应用/文档名、账户或网络标识。
- 用户可随时清空并导出匿名本地数据；核心找回和清理功能不依赖 Diagnostics。

关联验证：`P-08`、`P-09`。

### US-C08：让应用随工作流常驻但不打扰桌面

作为日用工具用户，我想关闭主窗口后仍能保留剪贴板能力，并能自行决定是否开机启动，
从而让 ClipRiva 接近系统工具而非占用工作空间的普通窗口。

验收条件：

- 关闭主窗口时，应用隐藏到菜单栏而不是退出。
- 菜单栏提供 Capture 状态、打开 Quick Paste、History、Settings 和明确退出入口。
- 用户可选择是否在登录时启动 ClipRiva。

关联验证：发布兼容性矩阵中的“安装与启动”“Quick Paste Restore”。

## ClipRiva Labs 用户故事（默认关闭）

Labs 不属于 Core 的必要工作流。以下故事仅在用户主动在 Settings 启用 Labs 后成立；所有处理
仍在本机完成，且不保证跨版本稳定性。

### US-L01：查看本地生成的内容摘要

作为愿意尝试实验功能的用户，我想查看对已保存文本的本地摘要和标签，
从而更快判断某条历史记录是否是我要找的内容。

验收条件：

- Labs 开启后，文本记录详情可显示确定性的本地摘要、分类和标签。
- 敏感派生预览使用脱敏内容。
- Labs 关闭时，这些内容不显示，也不为新复制内容生成 enrichment。

关联验证：`P-05`、`P-06`。

### US-L02：尝试本地实验检索

作为需要从较多历史中找内容的用户，我想试用实验检索并看到其结果依据，
从而判断它是否比标准搜索更适合我的内容。

验收条件：

- Labs 开启后，用户可在搜索框旁从标准 FTS 切换到 Labs retrieval。
- 检索在本地使用确定性的词法排序，并显示本地评分。
- Labs 关闭时，实验检索入口和对应后端能力均不可用。

关联验证：`P-05`、`P-06`。

### US-L03：执行受限的本地文本操作

作为希望快速整理文本片段的用户，我想执行明确允许的本地转换，
从而不将内容交给外部服务也能完成简单处理。

验收条件：

- Labs 开启后可从选中文本的详情或上下文操作中使用大写、小写、裁剪空白、规范化空白和 JSON 格式化等受限转换。
- Labs 不创建全局导航或独立工作台；关闭后入口、派生内容和对应后端能力均不可用。
- 操作结果复制回系统剪贴板。
- 审计记录仅保存内容哈希和脱敏预览；不执行云端操作。

关联验证：`P-06`、`P-07`。

## 故事优先级与发布判断

| 优先级 | 故事 | 发布判断 |
| --- | --- | --- |
| P0 | `US-C00`、`US-C02`、`US-C04`、`US-C06`、`US-C07` | 任一首次找回状态失真、恢复失败、不可逆清理、错误重复分组、误捕获敏感内容或权限越权问题，均阻断日用 Beta 结论。 |
| P1 | `US-C01`、`US-C05`、`US-C08`、`US-C09` | 影响信任、设置可理解性、直接粘贴降级、诊断可控性或常驻可靠性，应在 v1 前完成真实机器验证。 |
| 实验 | `US-L01` 至 `US-L03` | 不阻断 Core 发布；必须保持可关闭、离线且不影响 Core。 |

实际测试结果应记录在 [beta-validation-matrix.md](beta-validation-matrix.md)。如果用户故事和
实现不一致，以 Core 的隐私边界、[roadmap.md](roadmap.md) 和已确认的 Beta 行为为准。
