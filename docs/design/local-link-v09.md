# Local Link v0.9 设计与交互规格

- **状态：** Preview / Alpha 工程规格
- **适用范围：** Devices、Pairing、Send、Incoming、Transfers 及其入口
- **产品来源：** [`../product/local-link-v09.md`](../product/local-link-v09.md)
- **状态来源：** [`local-link-v09-state-matrix.md`](local-link-v09-state-matrix.md)
- **安全来源：** [`../security/local-link-boundary.md`](../security/local-link-boundary.md)

> **当前实现差异：** 本文是目标交互规格。当前生产 listener、Bonjour、真实配对和远端投递
> 继续 fail-closed；Devices/Pairing/Send/Incoming/Transfers 的浏览器状态属于 UI fixture。
> Native reveal 当前只证明 opaque transfer ID 与 `void` IPC seam；锁屏、用户切换、超时、撤销、
> disable/exit 时强制关闭已显示原生视图仍是后续原生生命周期与双真机门槛。

本文把 v0.9 产品路径落实为可实现、可测试的 macOS 交互规范。配图只用于表达信息层级；实现不得
把参考图、fixture 或概念页面当作真实网络能力证据。

## 设计原则

1. **像轻量 macOS 工具，而不是设备控制台。** Local Link 仅在用户主动发送、收到请求或管理
   设备时出现。
2. **一个界面一个主动作。** 等权危险动作不与主动作共享高亮权重。
3. **用户语言优先。** 工程状态保留在 native state machine；界面只显示原因、送达结论和下一步。
4. **正文最小暴露。** 通知、React/WebView、Transfers 和诊断只显示元数据；正文按需进入原生
   安全视图。
5. **不打断 Core。** 网络错误使用状态行、toast 或局部面板，不覆盖 History 主工作区。
6. **状态可复核。** 设备、配对、发送、接收与 Transfers 使用同一枚举和 Receipt 投影。

## 视觉基线

| 类别 | 规范 |
| --- | --- |
| 窗口 | Quick Paste 420×480；Devices 520×650；Pairing、Send、Incoming 目标 600–650×560–600；避免接近全屏 |
| 圆角 | 控件 8–10 px；卡片 12–14 px；窗口 16–18 px |
| 边框与阴影 | 1 px 低对比边框；阴影只用于浮层；不使用厚重发光边框 |
| 间距 | 8 pt 基础；元素 8/12；模块 16/20；页面 24/28 |
| 字号 | 窗口标题 16–18；模块标题 13–14；正文 12–13；辅助信息 11–12；配对码 48–56 |
| 颜色 | 薄荷绿用于主操作、在线与安全；琥珀用于等待/警告；红色只用于失败/撤销；必须同时有文字和图标 |
| 按钮 | 每个界面最多一个高亮主按钮；Cancel/Reject 使用次级或危险样式 |
| 遮罩 | 40–55% 半透明加轻模糊；保留来源上下文；避免全屏纯黑重遮罩 |
| 动效 | 150–220 ms；阶段推进使用局部状态变化；遵守 Reduce Motion |
| 点击区 | 所有主路径交互目标不小于 44×44 px |

窗口尺寸是设计目标，不得通过固定高度截断系统大字体、中文换行或 VoiceOver 辅助内容。内容超出
时优先自然扩展或滚动，不能缩小到不可读字号。

## 页面与入口

### Settings · Local Link

Settings 只表达同意与入口，不承担设备控制台职责。

- 显示 Local Link 总开关、Preview 标签、局域网/无账户/无云中继说明、系统局域网权限状态和
  “管理设备”。
- 首次明确开启时，先解释网络用途，再触发系统 Local Network 授权；不得在首次启动、打开
  History 或仅进入 Settings 时提前请求。
- 权限被拒绝时，开关状态与实际运行状态必须区分，显示“局域网访问已关闭，未开始发现”，并
  提供进入系统设置的动作。
- 关闭后立即停止 browse、publish、listener 和 session，清除待决正文；仍允许查看并撤销
  已保存的可信设备。
- 不显示完整设备列表、配对记录、协议阶段或 Transfers。

### Devices

Devices 是紧凑设备面板，按“本机 → 在线可信设备 → 需处理 → 离线设备 → 添加设备”排列。

- 标题使用 `Local Link`，Preview 为弱标签，不与开关混淆。
- 本机身份只显示设备名和短指纹；完整指纹位于折叠的“安全详情”。
- 设备卡仅显示 `在线 · 已信任`、`离线`、`需要重新配对` 或 `已阻止`，每张卡只有一个主动作。
- 在线可信设备主动作是“发送”；离线设备是“查看”；身份变化设备是“重新配对”；撤销放在
  更多菜单或明确的危险确认中。
- 撤销确认必须显示设备名和短指纹；即使 Local Link 关闭或设备离线也可执行。
- “添加设备”仅在点击后打开 60 秒窗口；关闭窗口、超时或切换主界面立即停止临时可见性。

空态与异常文案：

- 未发现设备：同一 Wi-Fi、对方 App 已打开、Local Link 已开启、局域网权限/防火墙共四项；
  提供“重新扫描”。
- 版本不兼容：“对方版本过旧，暂时无法配对。请在两台 Mac 上更新 ClipRiva。”
- 身份变化：“设备身份已变化，需要重新配对。旧信任已停止使用。”
- 权限被拒绝：“ClipRiva 未获得局域网访问，当前没有监听或发现设备。”

### Pairing

普通用户的主任务是核对设备名和六位码；协议术语与完整指纹默认折叠。

- 初始焦点位于“确认此设备”；`Esc` 取消；Tab 顺序固定为确认、取消、安全详情。
- 主层显示双方设备名、同一六位码、短指纹、对方确认状态和倒计时。
- 文案使用“在两台 Mac 上核对同一个配对码”和“等待对方确认”，不使用
  “Confirm the same device” 或 “Waiting for other Mac”。
- 信任只在双方确认后成立；一侧确认不得提前把设备移入可信列表。
- 成功后返回 Devices 并短暂显示“已建立可信连接”。取消、超时、不匹配、重复或身份变化均
  返回可解释状态，不留下半信任设备。
- 同一时间只允许一个 Pairing 主表面；Pairing 与 Send/Incoming 主表面互斥。

### Send

Send 只回答“这一条、这个设备、当前阶段”。

- 条目摘要显示类型、UTF-8 字节数和单行截断。该摘要来自发送端现有本地 Item；不得创建新缓存
  或进入 Transfers。
- 默认选择最近使用且在线的可信设备；离线、需重配、不兼容或被阻止设备不可发送并显示原因。
- 用户阶段只显示“检查发送策略 → 建立安全连接 → 等待接收 → 完成”。Noise、nonce、framing
  等协议细节仅出现在折叠安全详情或开发日志的固定无内容字段中。
- `Cancel` 在所有非终态可用。取消后会话不可恢复，必须回到仍存在的本地 Item 发起新请求。
- 最终只显示 Receipt 映射：对方已复制、对方已保存、对方已拒绝、已取消、已过期、未送达。
- Receipt 丢失或乱序时保持“正在确认结果”，由原生层进行幂等查询；不得猜测“已送达”。若
  无法收敛，该候选构建为 No-Go。
- 错误文案包含下一步，例如“设备已离线，文本未送达。请确认两台 Mac 在同一网络后重新选择
  原条目发送。”

键盘：上下键选择设备；`Enter` 确认发送；`Esc` 在未发送时关闭，在发送后触发 Cancel 确认；
焦点关闭后返回原条目动作。

### Incoming 与系统通知

系统通知只用于提醒，不用于预览。

- 通知正文固定为“某可信设备发来一段文本”，可附剩余时间；不得包含正文、首行、来源 App、
  路径、摘要哈希或系统剪贴板内容。
- 通知授权只在用户已开启 Local Link 且功能需要后台提醒时按上下文请求。授权被拒绝后使用
  菜单栏状态与应用内无正文提示，不改变请求安全边界。
- 点击通知后打开 Incoming 元数据卡。若 Pairing、Send 或系统安全阻断表面正在显示，请求进入
  待处理指示，但 60 秒正文生命周期不暂停、不延长。
- Incoming 卡显示可信设备、类型、字节数、倒计时和三个动作；默认焦点为 Copy。
- `Copy` 下方说明“只写系统剪贴板，不保存到 History”；`Save` 说明“只保存到本机 History，
  不改系统剪贴板”；`Reject` 说明“两者都不写，立即清除”。
- 快捷键：`⌘C` Copy、`⌘S` Save、`Esc` Reject。所有快捷键只调用原生 transfer ID 动作，
  不读取正文。

#### 原生安全视图

“显示内容”必须打开由原生进程持有的 AppKit 安全视图，而不是 React 组件、WebView 页面或
JavaScript 字符串。

- React 只可提交 opaque `transfer_id` 和“显示”意图；命令响应只返回成功/失败和 UI-safe
  元数据，绝不返回正文。
- 原生视图从同一 native pending buffer 临时绘制正文；关闭、锁屏、用户切换、超时、撤销、
  disconnect、disable、app exit 时立即隐藏并清理。
- 正文不得进入 DOM、WebView devtools、Tauri event payload、accessibility value cache、系统
  通知、日志、诊断、截图 fixture 或 Transfer model。
- 显示本身不产生终态，也不写剪贴板或 History。
- 原生视图必须支持键盘滚动、文本选择禁用或受控策略、VoiceOver 的最小必要朗读策略以及系统
  大字体；任何额外辅助功能暴露都必须经过安全评审。

### Transfers 与本地诊断

Transfers 是状态摘要，不是第二份 History。

- 只允许方向、可信设备显示名、时间、固定 `text` 类型、字节区间、终态、有限失败原因和
  内容无关诊断编号。
- 最多 20 条、最长 24 小时；支持 All、Received、Sent、Failed 过滤和手动清除。
- 不允许正文、首行、preview、digest、来源 App、路径、端点、完整/短指纹、session key、nonce、
  raw library error 或旧正文 Retry。
- “复制诊断编号”只复制不可还原正文、不可跨安装长期关联用户的随机编号。
- “导出本地诊断包”若进入 v0.9，只能在显式确认后导出固定字段，并在导出前显示排除项；不得
  自动上传。

## 单一主表面与焦点协调

优先级从高到低为：系统安全/权限阻断、Pairing、Incoming 决策、Send、Devices、Transfers、
Item Details。任一时刻最多一个需要决策的主表面。

- 新 Incoming 不得覆盖系统权限、配对确认或正在提交的接收动作；使用无正文指示器。
- 打开 Send 或 Transfers 时自动关闭 Item Details；关闭后焦点返回触发器。
- 锁屏或用户切换不只是视觉隐藏，必须通知原生状态机取消或拒绝待决正文。
- 主表面关闭后，焦点回到触发它的条目、设备卡或菜单入口；触发器消失时回到最近安全容器。
- 不使用仅靠 z-index 的多个同时存在 dialog。

## 状态与文案投影

界面不得根据零散布尔值拼接状态。每个组件接收
[`local-link-v09-state-matrix.md`](local-link-v09-state-matrix.md) 定义的单一枚举和有限失败原因。

以下文案禁止作为主要用户状态：`transportUnavailable`、`needsRePairing`、`Final`、
`captureBlocked`、`Noise XX`、`nonce`、`framing`。它们分别投影为“未送达”“需要重新配对”“已完成”
或具体终态、“受到隐私保护，无法发送”以及折叠安全详情。

## Accessibility 验收

- 所有状态使用文字、图标和可访问名称；颜色只作辅助。
- VoiceOver 按设备、类型、大小、剩余时间、当前状态、动作、副作用顺序朗读。
- 倒计时不是唯一提示；最后 10 秒不使用每秒抢占式播报。
- Tab 顺序稳定；`Esc` 语义与可见 Reject/Cancel 一致；快捷键不会绕过确认或策略。
- Reduce Motion 下移除非必要进度动画；高对比度和系统大字体下无截断或重叠。
- 同一操作不会被鼠标与键盘重复触发两次。

## 设计验收交付物

每个 Epic 必须提交以下证据，且不得含真实剪贴板内容、设备名、指纹或网络端点：

1. Devices：关闭、未发现、在线可信、离线、需重配、权限拒绝。
2. Pairing：等待双方、单侧确认、成功、取消、超时、不匹配、版本不兼容。
3. Send：策略检查、连接、等待、Cancel、六种终态和有限失败文案。
4. Incoming：无正文通知、隐藏元数据卡、原生按需显示、Copy/Save/Reject、锁屏清理。
5. Transfers：空态、过滤、20/24 清理、诊断编号、无 Retry。
6. 键盘、VoiceOver、Reduce Motion、系统大字体和焦点恢复记录。

浏览器 fixture 截图只能证明布局，不证明原生安全视图、系统通知、网络、Keychain、Receipt 或
双 Mac 行为。
