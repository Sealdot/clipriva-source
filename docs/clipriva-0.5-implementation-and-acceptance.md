# ClipRiva 0.5 实施方案与验收基线

- **版本主题：** Fast Recall / 轻量找回
- **方案日期：** 2026-07-26
- **文档状态：** 0.5 本地实现与自动化验收已完成；真实 macOS 发布候选验收仍待执行
- **产品输入：** `ClipRiva-0.5-下一版本产品方案.docx`

## 1. 版本目标

0.5 只围绕一条高频路径收敛体验：

> 复制内容 → 唤起 Quick Paste → 确定性找到目标 → 安全粘贴或降级复制。

发布判断不以功能数量为标准，而以以下可验证结果为标准：

1. Quick Paste 成为日常入口，找回内容不需要先打开完整 History。
2. 常用操作可由键盘完成，从唤起到粘贴不超过 3 次键盘操作。
3. 没有 macOS 辅助功能权限时，搜索、选择和复制仍然可用。
4. 相同内容显示为一个 Item，并以 Occurrence 解释复制次数与来源；格式差异显示为
   Variant，不再向用户展示含义模糊的“内容版本”。
5. 普通删除均可恢复；永久删除只存在于回收站，并有明确的不可撤销确认。
6. 暂停记录、忽略 App 和本地诊断都使用具体、可验证的行为说明。

## 2. 范围与非目标

### P0：Beta 阻断项

| 模块 | 交付内容 | 发布判断 |
| --- | --- | --- |
| Quick Paste 核心闭环 | 全局快捷键唤起、搜索、默认选择、直接粘贴、降级复制、关闭和焦点返回 | 任何失败都不丢内容，不向错误目标发送粘贴 |
| 搜索与排序 | 精确、前缀、包含匹配；固定并列排序；命中反馈和空状态 | 结果顺序可解释，1 万条历史的常规搜索达到性能目标 |
| Item / Occurrence / Variant | 新模型、稳定 ID、兼容迁移、重启恢复 | 升级不丢历史、来源、格式、置顶或回收站状态 |
| 删除与恢复 | 普通删除入回收站、短时撤销、恢复、到期和永久删除 | 主历史不存在不可恢复的普通删除路径 |
| 页面分层 | Quick Paste、菜单栏状态入口、紧凑 History、低频 Settings/Labs | 日常粘贴不打开完整主窗口 |
| 稳定性 | 权限变化、焦点变化、异常退出、全屏、多显示器 | 自动化可验证部分通过，真人 macOS P0 矩阵有证据 |

### P1：P0 稳定后的收口项

| 模块 | 交付内容 | 发布判断 |
| --- | --- | --- |
| 捕获控制 | 菜单栏和设置中的暂停/继续、忽略指定 App、状态说明 | 规则在任何 Item、Occurrence、Variant、blob 或派生数据写入前执行 |
| 内容展示与粘贴方式 | 长文本、代码、URL、图片、文件引用、保留格式和纯文本粘贴 | 常见内容可辨认，失效资源有明确反馈 |
| 本地诊断 | 查看、导出、清空固定事件数据 | 默认关闭，不记录正文、路径、文件名、窗口标题或可复原标识 |

### 0.5 明确不包含

- 账号、同步、云端备份、跨设备冲突合并或相关入口。
- 云端 AI、MCP、Agent、自动改写、翻译或图片语义理解。
- Windows、Linux、移动端和浏览器扩展。
- 模型驱动的语义搜索、模糊去重、自动分类或大规模 Labs 扩展。
- 签名、公证、发布、标签或推送；这些动作仍受发布清单和维护者授权控制。

## 3. 关键架构决策

### 3.1 三类记录对象

| 对象 | 责任 | 用户可见表达 | 约束 |
| --- | --- | --- | --- |
| Item | 一份按本地完全相同内容折叠的主体 | History 中的一条内容 | 置顶、删除、恢复和稳定 ID 均作用于 Item |
| Occurrence | 每次捕获或再次出现的时间、来源 App、本地设备和使用上下文 | “已复制 N 次”、最近来源和时间线 | 只用于解释来源与活动，不成为可独立删除的正文副本 |
| Variant | 同一 Item 的纯文本、RTF、HTML 或其他可恢复表示 | 详情中的格式选项 | 不称为“内容版本”，不得改变原 Item 的正文语义 |

只有本地完全相同的内容才合并。大小写、空格、换行或任何文本差异仍是不同 Item。
stable ID 和 device ID 保留在本地数据层，为未来独立设计的迁移或同步协议留出兼容
空间，但 0.5 不提供同步入口。

实现上继续以 `clipboard_items` 的 canonical 行承载 Item，以
`clipboard_occurrences` 承载 `{id, source_app, device_id, occurred_at}`，并复用
`clipboard_representations` 承载富文本、图片和文件引用等 Variant。`search_text` 只在
本地数据库中保存正文与文件 basename，不通过 IPC 序列化，也不保存完整文件路径；
`last_used_at` 用于确定性排序。

### 3.2 确定性搜索

搜索只使用本机数据，不调用模型或网络：

1. 正文或文件名完全匹配。
2. 正文或文件名前缀匹配。
3. 正文、文件名或来源 App 包含匹配。
4. 相同匹配等级内，置顶 Item 优先。
5. 最后按最近一次复制或使用时间排序，并用稳定 ID 打破完全并列。

完整本地文件路径不进入搜索索引。搜索命中旧 Occurrence 时返回所属 Item，并在详情
中标识命中的 Occurrence。任何性能优化都不得改变以上排序。

### 3.3 Quick Paste 状态机

| 事件 | 成功路径 | 失败或无权限路径 |
| --- | --- | --- |
| 打开 | 记录原目标应用；聚焦搜索；默认选中最近可用 Item | 不打开完整 History |
| `Enter` | 恢复选中表示，返回目标应用并发送粘贴事件，随后关闭 | 先恢复到系统剪贴板；保留查询、选择和滚动位置；显示手动 `Command-V` 提示 |
| `Command-Enter` | 写入纯文本表示并尝试粘贴 | 同样降级为纯文本复制，不修改原 Item/Variant |
| `Command-C` | 复制选中内容并提示 | 不关闭面板 |
| `Command-P` | 置顶或取消置顶 | 选择状态保持 |
| `Escape` | 有搜索词时先清除搜索；无搜索词时关闭 | 焦点返回原应用 |

第一次启动、查看历史或打开 Settings 都不主动申请辅助功能权限。只有用户第一次执行
需要模拟粘贴事件的直接粘贴操作时，才解释权限用途与“不授权仍可复制”的替代方案。
权限拒绝、撤销、目标应用退出、目标切换或事件发送失败时，不得向未确认的应用发送
输入。

### 3.4 删除和保留

- 主 History 的单条删除直接移入本地回收站，并提供短时按钮撤销和 `Command-Z`。
- 置顶 Item 可被用户主动单条删除，但界面必须明确提示其置顶状态。
- 批量清理继续先展示影响数量、置顶跳过数量、规则和恢复窗口；预览不回显正文。
- 回收站恢复窗口固定为 Default 7 天、Strict 1 天，从移入回收站时开始计算；不再因
  active history 的 `retention_until` 剩余时间而缩短。
- 单条永久删除和清空回收站均需二次确认；清空需展示数量和空间影响。

## 4. 数据迁移策略

0.5 迁移必须是可重试的本地原子迁移。实现前先复制含历史的测试数据库，禁止用唯一
的真实用户数据库作为迁移样本。

### 迁移步骤

1. 在同一事务内扩展 Item 字段、创建 Occurrence 结构和索引；Variant 继续使用现有
   representation 结构。
2. 以旧 `group_id` 为候选组，只在可证明内容身份完全相同时归并；canonical Item
   选择最早 `created_at`，再以稳定 `id` 打破并列。不得做大小写、空白或模糊归一化。
3. 将每条旧捕获记录转换为 Occurrence，保留时间、来源 App 和本地设备信息。
4. 保留已有 RTF、HTML、图片或文件引用 representation，并由 Item 将其作为 Variant
   暴露。旧数据库若无法在 SQL 迁移内重新计算表示身份，则只合并可安全证明等价的
   行；不确定的旧富文本行保持独立，优先保证不误合并和不丢数据。
5. 合并 Item 状态时必须使用显式规则保留 stable ID、置顶、保留期限、删除状态、
   回收站期限、恢复时间和 blob 引用。
6. 生成只含正文或文件 basename 的本地 `search_text`，设置 `last_used_at`，重建并
   验证搜索索引、外键和 blob 引用后才提升 schema version。
7. 任一步失败都回滚到旧 schema；应用不得在部分迁移状态继续运行。

### 自动迁移用例

- 空库和仅有偏好的库。
- 含完全相同、仅大小写不同、仅空格不同和仅换行不同的文本。
- 含多个来源、多个时间点和置顶状态的旧重复组。
- 含 RTF/HTML、图片和单/多文件引用的记录。
- 无法证明与纯文本等价的旧 RTF/HTML 行保持独立，同时所有 representation 和
  Occurrence 均可读取；该兼容限制不得被报告为“全部旧格式已折叠”。
- 活跃、回收站中、已恢复和即将到期的记录。
- 强制迁移失败后重开数据库并重试。
- 迁移后重启，检查外键、搜索索引、稳定 ID、Occurrence 数量和 blob 可读性。

### 回滚原则

迁移前备份是实机 Beta 的前置条件。代码迁移失败依靠数据库事务回滚；如果已成功
迁移并写入 0.5 新数据，则不得把 0.5 数据库直接交给旧版本打开。降级需要恢复迁移前
备份，不通过逆向猜测重建旧 schema。

## 7. 风险与缓解

| 风险 | 影响 | 缓解与回滚 |
| --- | --- | --- |
| 旧 duplicate group 合并错误 | 历史、来源或置顶丢失 | 精确哈希边界、事务迁移、迁移前备份、逐对象计数 |
| Variant/blob 引用错误 | 图片或富文本不可恢复 | FK 与 blob 可读性测试；失败不提升 schema version |
| 旧富文本缺少可重算的表示身份 | 不能安全折叠到对应纯文本 Item | 不确定时保持独立；记录兼容限制，不以猜测换取表面折叠率 |
| 辅助功能误投目标 | 向错误 App 发送输入 | 记录并复核原目标 PID；任何不确定状态都只复制 |
| 权限请求过早 | 首次体验被阻断 | 只在第一次直接粘贴动作触发；设置仅说明和检查状态 |
| 搜索性能优化改变顺序 | 结果不可预测 | 固定排序契约和 adapter parity 测试 |
| 删除撤销竞态 | 误恢复或永久丢失 | Item 级状态机、撤销时限测试、永久删除仅接受回收站 Item |
| 诊断字段扩张 | 泄露正文或上下文 | 有限枚举和列级测试；默认关闭；变更先更新隐私文档 |
| 性能门槛受机器波动影响 | CI 假失败或错误通过 | 普通 CI 验证正确性，统一 release/macOS 基准记录 p50/p95 |
