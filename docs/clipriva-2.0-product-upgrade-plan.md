# ClipRiva 2.0 product experience upgrade plan

> Historical P0–P2 plan. For the current alpha.2 scope, status, dependencies and evidence, use the [single execution ledger](planning/clipriva-2.0-execution.md). The current review proposes an on-demand Inspector instead of this plan's permanent Inspector.

- **Status:** implementation plan
- **Branch:** `codex/clipriva-p0-p2-product-upgrade`
- **Date:** 2026-08-12
- **Visual direction:** selected Product Design option 2, “Native Library Workspace”
- **Product promise:** recover, reuse and organize clipboard content locally without an account or
  an implicit network boundary.

This plan implements the approved P0-P2 product audit recommendations in order. It does not approve
publication, signing, notarization or promotion of Local Link from Preview to Stable.

## 1. Product hierarchy

ClipRiva uses three frequency layers:

| Layer | User question | Product surface |
| --- | --- | --- |
| High frequency | “Where is the thing I copied?” | Quick Paste: search, navigate, restore, preview and actions |
| Medium frequency | “How do I keep and reuse this?” | History, Saved and Collections with a stable inspector |
| Low frequency | “What may ClipRiva store or connect to?” | Privacy, Local Link Preview and local diagnostics |

The main workspace follows the selected design reference:

- left source rail: History, Saved and Collections;
- center: scoped search, active filter tokens and a lightweight result list;
- right: stable, non-overlay inspector with one primary action and a unified action menu;
- Local Link Preview and Privacy remain secondary tools;
- Queue is a collapsible helper, not the main information architecture.

The existing dark graphite and mint visual language remains. Informational text is at least 11 px
and ordinary text targets a 4.5:1 contrast ratio. No new raster or third-party visual assets are
required for the implementation; the concept image was generated by OpenAI ImageGen in this task
from current ClipRiva screenshots and is used only as a design reference.

## 2. P0 — trust and core-flow correction

### Implementation

1. Make first value a single task: privacy confirmation, copy two items, open Quick Paste, recover
   the first. While this guide is active, incoming cards and other coaching surfaces do not render.
2. Replace independent overlay booleans with a single main-surface state. Details, Settings,
   Incoming, Transfers, Send, cleanup and Recycle Bin are mutually exclusive and restore focus.
3. Project Local Link device status through global preferences. When Local Link is off or still
   loading, stale device rows can never display Online or Sendable.
4. Keep only History and Saved/Collections as primary destinations. Put Local Link Preview,
   Incoming and Transfers under a secondary tools entry.
5. Make search scope visible. History and Saved may retain their own query; Local Link clears the
   clipboard query.
6. Raise secondary-text contrast and information text size without inflating decorative badges or
   keyboard glyphs.

### Acceptance cases

- `P0-ONB-01`: after privacy confirmation, exactly one first-value task is visible and no Local Link
  request competes with it.
- `P0-ONB-02`: a successful Quick Paste recovery permanently ends the guide.
- `P0-SURF-01`: opening any main surface atomically closes the previous surface.
- `P0-SURF-02`: Escape closes only the active surface and focus returns to its trigger.
- `P0-LL-01`: `enabled=false + trusted + stale online=true` is not displayed as Online/Sendable.
- `P0-LL-02`: the same device becomes Sendable only after preferences and readiness are enabled.
- `P0-NAV-01`: History and Saved/Collections are primary; Local Link is labelled Preview in
  secondary tools.
- `P0-SEARCH-01`: the visible and accessible search label identifies its current scope.
- `P0-A11Y-01`: informational text is at least 11 px and meets 4.5:1 contrast on its surface.

## 3. P1 — everyday reuse

### Data model

P1 deliberately reuses existing local fields instead of adding a migration:

- `clipboard_items.is_pinned` becomes the Saved/Snippet retention fact;
- `clipboard_item_tags.label` becomes Collection membership;
- an item may belong to multiple Collections;
- Collection names keep the existing limit of 8 per item and 24 characters per name;
- legacy Pins and Tags appear immediately as Saved and Collections.

No empty Collection, custom icon, colour or drag ordering is introduced in this iteration.

### Implementation

1. Fix native list results so tags/Collections are attached in every search branch.
2. Move type, source, time, Saved, Collection, recent-use and Local Link filters into the Rust
   query before `LIMIT`; facets are derived from the whole active inventory rather than the first
   100 rows.
3. Add local Collection aggregation plus transactional save/remove/rename/delete membership
   operations. Deleting a Collection never deletes clipboard content.
4. Add one reusable Action Panel. Context controls which of Restore, Restore as Plain Text, Copy,
   Save, Collections, Queue, Local Link and Recycle Bin actions are available.
5. Reduce Quick Paste help to Navigate, Restore and More; move type filters and secondary actions
   into popovers/panels.
6. Reorganize Settings into General, Privacy and Shortcuts. Advanced local tools and diagnostics
   become disclosed secondary sections.

### Acceptance cases

- `P1-FILTER-01`: a matching item outside the first 100 rows remains discoverable by combined
  filters.
- `P1-FILTER-02`: query, kind, source, Collection, time and Saved filters combine without SQL
  injection or client-side truncation.
- `P1-COL-01`: legacy tags render as Collections and legacy pins render as Saved.
- `P1-COL-02`: save plus Collection membership is atomic; unsaving preserves membership but returns
  the item to normal retention.
- `P1-COL-03`: renaming into an existing Collection merges membership without duplication.
- `P1-COL-04`: deleting a Collection does not delete, unpin or expose clipboard content.
- `P1-ACT-01`: one Action Panel supports keyboard navigation, Escape and trigger focus restoration.
- `P1-ACT-02`: destructive Saved-item removal uses the existing Recycle Bin preview and explicit
  include-pinned contract.
- `P1-QP-01`: the default Quick Paste footer contains only three help groups.
- `P1-SET-01`: Settings has three primary sections and preserves all current preference behaviour.

## 4. P2 — differentiated local capabilities

### 4.1 Privacy Activity

Productize the existing content-free `uncaptured_clipboard_events` as an always-available Privacy
Activity inside Privacy. It remains separate from optional reliability diagnostics.

- show all bounded recent reasons, their source application and relative time;
- retain at most 20 rows for 7 days;
- never store clipboard content, preview, hash, item ID, filename, path, peer or endpoint;
- clearing Activity does not change History, preferences, diagnostics or Local Link.

### 4.2 Temporary sequential Queue

Queue is process-memory state containing at most 20 clipboard item IDs, order and cursor. It stores
no content and clears on application restart.

- enqueue follows visible order and deduplicates IDs;
- successful restore or paste advances exactly once;
- failed paste retains the current item and offers Retry, Copy and advance, or Skip;
- deleted/recycled items become Unavailable and are never silently substituted;
- main and Quick Paste stay synchronized through named events;
- Queue does not change Local Link's no-offline-body-queue claim.

### 4.3 Privacy Cover

Privacy Cover is an explicit presentation mode, not a promise to block all system screen capture.

- when enabled, sensitive text, OCR, tags, sources, filenames and images are not created in the DOM
  or accessible names;
- existing inspectors, previews and native Local Link reveal surfaces close immediately;
- enabled state is known before content surfaces render after launch;
- Tauri content protection is applied as best-effort hardening only;
- no process scanning, meeting-app detection or Screen Recording permission is introduced.

### 4.4 Local image OCR

OCR uses macOS Vision on image bytes ClipRiva already captured. It introduces no network request,
account, remote model or new OS permission.

- automatic OCR is default off; manual “Extract text locally” is available for an existing image;
- output is capped at 256 KiB and stored in a dedicated item-owned table plus FTS index;
- OCR text follows item recycle/restore/permanent-delete lifecycle;
- sensitive output is checked before persistence and never enters Local Link, diagnostics or logs;
- deleting all extracted text leaves images and other History intact;
- a single cancellable worker bounds CPU and memory use.

### P2 acceptance cases

- `P2-PA-01`: Activity empty/list/clear/expiry states are accurate and content-free.
- `P2-SQ-01`: Queue deduplicates, caps at 20 and synchronizes windows.
- `P2-SQ-02`: a successful action advances once; failure and concurrent activation do not advance.
- `P2-SQ-03`: restart clears Queue and SQLite/WAL contains no Queue IDs or content.
- `P2-PC-01`: Privacy Cover removes protected content from DOM and accessible names on every surface.
- `P2-PC-02`: restart with Cover enabled never flashes content before preferences load.
- `P2-PC-03`: no Screen Recording, Camera or Photos permission is added.
- `P2-OCR-01`: OCR is default off and existing image capture is unchanged.
- `P2-OCR-02`: synthetic Chinese/English image text is locally searchable as `Text in image`.
- `P2-OCR-03`: sensitive OCR is not persisted; new-image automatic OCR fails before blob storage.
- `P2-OCR-04`: deletion clears OCR/FTS while preserving images; permanent item deletion cascades.

## 5. Local Link release boundary

The task may complete the product UI, fail-closed states, automated tests, evidence scripts and
release wording. It cannot manufacture the following external evidence:

- 50 authenticated pairing ceremonies on two real Macs;
- 200 real text transfers and Copy/Save/Reject samples;
- sleep, lock, user-switch, network-change, firewall and AP-isolation tests;
- packet capture and SQLite/WAL/blob/log marker scans;
- Keychain lifecycle and signed/notarized clean-machine installation;
- macOS 13/14/15/26, Apple Silicon/Intel and VoiceOver validation.

Until every gate is recorded against the same frozen signed artifact, Local Link remains default
off, labelled Preview and No-Go for public promotion. Git branch publication is not an application
release authorization.

## 6. Privacy, security, dependency and license follow-ups

P1 changes the product meaning of existing stored Tags/Pins. P2 adds OCR text, Queue memory flow and
Privacy Cover state. The same change set must update:

- `PRIVACY.md`;
- `docs/privacy/data-flow.md`;
- `docs/open-source/module-boundary.md`;
- `docs/security/THREAT_MODEL.md`;
- help, test inventory and acceptance documentation;
- privacy-boundary and migration tests.

If OCR adds a direct Rust dependency, update the direct-dependency inventory and rerun the complete
Node/Rust license and SBOM process in `docs/audit/sbom-license-review.md`. No credentials, real user
data, production endpoint or private path may enter fixtures or reports.

## 7. Completion gates

1. Focused unit/component tests for each acceptance case.
2. `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`.
3. `cargo fmt --check`, Clippy with warnings denied and `cargo test --locked`.
4. Privacy boundary, migration, large-history and release benchmark checks.
5. Browser screenshots of the selected visual target states at normal and minimum desktop sizes.
6. Product Design comparison loop with `design-qa.md` ending in `final result: passed`.
7. Dependency/license/SBOM review when manifests or locks change.
8. Focused commits, explicit impact handoff, branch push. No tag, release, signing or notarization.
