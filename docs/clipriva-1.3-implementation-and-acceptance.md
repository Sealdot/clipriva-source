# ClipRiva v1.3 迭代设计、测试与验收方案

- **输入：** `ClipRiva-v1.3-产品优化方案（含配图）.docx`（2026-07-30）与当前 v1.2 实现。
- **版本定位：** Reliable Local Transfer Beta 候选；在真实双 Mac Gate 完成前继续标记 Preview / Alpha，不对外宣称 Beta 已通过。
- **核心目标：** 用户在发送前知道“现在能不能发”，通过键盘完成一次显式发送，在接收端决定正文落点，并在失败时获得唯一、可执行的恢复动作。
- **明确不做：** 图片/文件传输、跨网或云中继、账号、同步、自动发送、广播、离线正文队列、旧正文自动重放、新通知权限。

## 现状结论

v1.2 已具备可复用的安全底座：Local Link 默认关闭；双端 SAS/指纹核对与三档信任期限；撤销后失效；文本正文只在原生进程内短暂存在；请求 60 秒过期；全局最多 3 个待处理请求；Copy / Save / Reject 互斥；活动记录、IPC DTO 和日志不含正文；失败原因与恢复动作由有限枚举表达。

v1.3 不重写协议或存储，主要补齐以下体验和验收缺口：

1. 多个技术状态尚未收敛为“可发送 / 需处理 / 离线”的统一结论。
2. Quick Paste 仍有独立确认页；未达到 `Command+Enter` 打开目标、`Enter` 直接确认的连续键盘闭环。
3. 待处理请求主要表现为浮动卡片，Devices 内缺少稳定入口和请求数量提示。
4. 失败文案虽完整，但活动页缺少面向“重新从当前条目发起”的明确入口。
5. 只有通用本地诊断导出，没有 Local Link 专用、字段白名单化且可预览的诊断包。
6. Devices、配对和传输活动的视觉层级尚未收敛到 v1.3 参考图。

## 实施设计

### 阶段 1：连接就绪与设备中心（US-410）

- 新增纯状态投影 `LocalLinkReadiness`，依次检查运行时网络访问、Local Link 开关、发现、信任和已认证在线状态。
- 只报告第一个阻断项，并只给一个主动作；文案统一为“可发送 / 需处理 / 离线”。
- Devices 顶部增加就绪结论与可展开的连接检查；设备列表继续区分在线、离线、需重新配对和已撤销。
- “在线”不得替代“可信”；只有 `trusted + online` 能进入发送路径。

### 阶段 2：双端配对（US-420）

- 保留原生生成的 6 位 SAS、双方短指纹、60 秒期限和双端确认，不允许 WebView 提供信任锚。
- 配对视觉收敛为三步：发现 → 双端核对 → 完成；默认 30 天，仍可选仅本次或始终信任。
- 撤销、身份重置、信任过期或核对失败后必须重新配对；不得自动恢复旧信任。

### 阶段 3：Quick Paste 显式发送（US-430）

- `Enter` 继续只复制到本机系统剪贴板并关闭，绝不发送。
- `Command+Enter` 打开同屏目标侧栏，默认选中最近成功且当前可发送的可信设备。
- 目标侧栏同时显示目标、Text 类型、字节数和短摘要；离线/未配对设备可见但不可发送。
- 选择设备不等于发送；侧栏内一次 `Enter` 或主按钮创建请求，`Esc` 返回 Quick Paste 并保留查询、筛选和选中项。

### 阶段 4：待处理请求、结果与恢复（US-440 / US-450）

- Devices 内增加稳定的待处理入口，展示待处理数量和当前请求；其他页面继续使用非阻断提示。
- 正文仍不进入 WebView；需要查看时只发送不透明 transfer ID，原生安全视图返回 `void`。
- Copy 仅写系统剪贴板；Save 仅写本地 History；Reject/过期不写正文。
- 活动列表只保留元数据。对可恢复失败显示“从当前条目重新发起”的动作语义，不提供旧正文重放。
- 失败原因必须映射到用户文案、唯一下一步和是否可重试；不确定或冲突回执一律按未送达处理。

### 阶段 5：无正文诊断导出（US-460）

- 增加用户主动触发的 Local Link 诊断包预览与导出；不上传、不自动采集、不创建新的正文存储。
- 采用字段白名单：schema/app 版本、生成时间、就绪结论、开关/发现状态、每次导出重新加盐的匿名设备引用、信任/在线状态、最多 50 条内容无关设备/传输记录、有限错误码与恢复动作。
- 明确排除：正文、预览、搜索词、源应用、真实设备名、完整设备 ID、完整指纹、IP/端口/endpoint、SSID、路径/文件名、密钥、nonce、payload digest。
- 导出前显示字段说明；下载只在用户明确点击后发生。

## 自动化与人工验收 Gate

### 工程 Gate（本任务可完成）

1. Biome、TypeScript、Vitest、Vite build 全部通过。
2. Rust format、Clippy、`cargo test --locked` 全部通过。
3. v1.3 新增的状态投影、键盘闭环、接收决定、失败映射、诊断白名单和文档边界测试通过。
4. 在浏览器开发夹具中按参考图对 Devices、配对、Quick Paste 侧栏和传输活动逐屏视觉验收；P0/P1/P2 视觉问题清零。
5. 不新增直接依赖、网络目的地、账号、遥测、远程模型、通知权限、正文存储或第三方资产。

### 真实双 Mac Beta Gate（环境外，保持 No-Go）

- G1：首次权限拒绝/允许、开关和重启。
- G2：至少 20 次 v1.3 配对循环，覆盖三档信任、撤销、过期、改名和重发现。
- G3：同一候选构建完成 200 条真实文本请求，正常局域网成功率至少 98%，覆盖 Wi-Fi、以太网+Wi-Fi 和睡眠唤醒。
- G4：AP 隔离、VPN、网络切换、接收方退出、拒绝、过期和中断恢复。
- G5：SQLite/WAL、日志、诊断包、临时文件和崩溃文件正文命中为 0。
- G6：Quick Paste 搜索 P95 < 80 ms、连续 2 小时无明显增长、网络线程不阻塞 UI。

在上述真实设备证据完成前，代码可以通过工程验收并提交，但发行状态必须继续是 Preview / Alpha；不得将模拟、单机、loopback 或同主机测试描述为真实双 Mac Beta 证据。

## 影响结论

- **隐私：** 新增用户主动触发、内容无关的 Local Link 诊断 JSON 导出；不上传、不记录正文、不新增持久化诊断表。必须同步更新三份边界文档和敏感字段阻断测试。
- **安全：** 不改变 Noise、Keychain、SAS、信任锚、正文内存期限、接收动作和无旧正文重放规则；UI 状态由安全的有限元数据投影。
- **许可证：** 计划不新增依赖、第三方代码、字体或资产，因此不触发 SBOM/许可证重跑；若实现中改变 manifest/lockfile，则必须按仓库规则补做审查。
