# Local Link v0.9 产品规格

- **状态：** Preview / Alpha 工程候选，不是 Beta 证据
- **建议用户可见名称：** Local Link Preview
- **目标平台：** macOS ↔ macOS
- **正文范围：** 单条、显式选择的 1 B–256 KiB UTF-8 文本
- **证据日期基线：** 2026-07-28

> **当前实现差异：** 本文定义完整 v0.9 产品目标，不代表当前工程检查点已开放网络。
> 当前生产 listener、Bonjour、真实配对、远端 session 与正文投递继续 fail-closed；本轮只交付
> Receipt/状态与身份/过期边界、内容无关 UI 和 opaque native-reveal seam。浏览器、单元或同机
> 测试只能用于工程预检，不能把下文七步目标改写为当前可用能力。

本文冻结 v0.9 的产品范围和用户闭环。状态名称以
[`local-link-v09-state-matrix.md`](../design/local-link-v09-state-matrix.md) 为唯一来源；正文生命周期与
禁止位置以 [`local-link-boundary.md`](../security/local-link-boundary.md) 为准；测试证据必须记录在
[`local-link-v09-matrix.md`](../qa/local-link-v09-matrix.md) 和
[`local-link-beta-evidence.md`](../release/local-link-beta-evidence.md)。

## 产品结论

v0.8 已建立默认关闭、本地优先、双方确认、接收端决定、内容无关 Transfers 和 fail-closed
边界，但生产适配器尚未完成真实 listener、Bonjour、双端配对和远端投递。v0.9 的任务不是扩展
更多内容类型，而是完成一次可解释、可取消、可核验的真实双 Mac 文本交接。

在两台真实 Mac 的同一签名候选构建通过完整物理矩阵前，所有界面、README 和证据必须继续使用
Preview / Alpha。浏览器 fixture、同机双进程、loopback、截图或 unsigned bundle 均不能支持
“Beta 可用”结论。

## 一句话定位

无需账户和云端，在同一局域网内，把当前选中的一条文本安全交给另一台可信 Mac，并由接收方
决定复制、保存或拒绝。

## 版本目标

- **G1｜真实闭环：** 两台真实 Mac 可完成发现、配对、认证加密、发送、接收、取消与回执。
- **G2｜轻量路径：** 首次配对完成时间 p95 不超过 90 秒；已配对设备从确认发送到接收卡出现，
  p50 不超过 2 秒、p95 不超过 5 秒。
- **G3｜可解释失败：** 每个失败都说明发生了什么、是否已送达以及下一步可以做什么。
- **G4｜受控正文：** 接收方决定前，正文不进入系统剪贴板、History、WebView、SQLite/WAL、
  Transfers、文件、日志或诊断。
- **G5｜Core 独立：** Local Link 关闭、失败、撤销、离线或受到异常流量时，History、Quick
  Paste、Recycle Bin、Capture 和 Direct Paste 保持原语义。

“首次配对 p95 ≤ 90 秒”包含用户找到入口和核对的总时长；“添加设备”网络可见窗口仍固定为
60 秒。发现结果的性能目标为 p95 ≤ 5 秒，10 秒仍无结果时进入可操作空态。

## 包含范围

| 能力 | v0.9 约束 |
| --- | --- |
| 平台与网络 | 两台 macOS 设备；同一可达局域网；Bonjour/mDNS 发现与认证加密 peer TCP |
| 用户同意 | 新安装和升级均默认关闭；仅用户明确开启后启动网络生命周期 |
| 配对 | 用户启动 60 秒窗口；同一握手转录、同一六位 SAS、固定身份、双方确认后才保存信任 |
| 内容 | 一次一条 1 B–256 KiB UTF-8 文本；发送前重新执行类型、大小与隐私策略 |
| 接收决定 | `Copy`、`Save`、`Reject` 三选一；正文只能在原生安全视图按需显示 |
| 取消与恢复 | Sender Cancel、超时、撤销、锁屏、用户切换、断连和退出共享原子清理路径 |
| 结果 | 双方收敛到同一 Receipt；Transfers 只保留内容无关摘要，最多 20 条、最长 24 小时 |
| 诊断 | 可复制内容无关诊断编号；若实现本地诊断包，只允许显式导出且使用固定字段白名单 |

## 明确非目标

- 图片、文件、富文本、文件夹或批量传输。
- 自动剪贴板同步、全历史同步、后台镜像或离线队列。
- 账户、Apple ID 绑定、云中继、互联网目录或团队空间。
- Windows、iOS、Android 客户端。
- 来源 App、文档名、路径、端点、密钥或正文出现在 Transfers/诊断中。
- 从旧 Transfer 恢复或重放正文。重试必须回到仍存在的本地 Item，创建新 session、transfer ID
  和 nonce。
- 以同名设备、IP、端口、Bonjour instance 或六位码本身作为信任锚。

任何新增能力只有在直接提高真实双 Mac 文本交接的成功率、可理解性或安全性时才可进入本版本；
否则进入 Later。

## 七步核心路径

| 步骤 | 用户动作 | 系统必须说明 | 失败出口 |
| --- | --- | --- | --- |
| 1. 开启 | 在 Settings 主动开启 Local Link | 仅局域网、无账户、无云中继，以及将出现系统局域网权限请求 | 拒绝权限或关闭开关后不监听、不发现、不保留会话 |
| 2. 发现 | 打开 Devices，选择附近设备 | 设备显示名、在线状态、兼容性；发现不等于可信 | 同一 Wi-Fi、对方 App、Local Link、权限与防火墙检查；可重新扫描 |
| 3. 配对 | 两台 Mac 核对同一六位码并分别确认 | 双方身份、剩余时间、完整指纹的折叠入口 | 取消、超时、不匹配或身份变化均不保存信任 |
| 4. 选择 | 从 History 或 Quick Paste 明确选择一条文本和一个可信设备 | 类型、字节数、目标设备；只处理这一条 | 非文本、空文本、过大、隐私策略阻止或设备离线时不构造 payload |
| 5. 发送 | 确认并观察策略检查、安全连接、等待接收 | 当前阶段、剩余时间、Cancel 的不可逆含义 | 任一阶段均可 Cancel；不提供旧正文 Retry |
| 6. 接收 | 点击无正文通知；按需在原生安全视图显示；选择 Copy、Save 或 Reject | 发送设备、类型、大小、倒计时和每个动作的准确副作用 | 锁屏、超时、撤销、断连、退出只产生一个终态并清除正文 |
| 7. 回执 | 双方查看同一结果 | Copied、Saved、Rejected、Cancelled、Expired 或 Not delivered | Receipt 丢失/乱序必须幂等查询收敛；未收敛不得猜测 Delivered |

## 信息架构

| 页面 / 入口 | 唯一职责 | 保留 | 删除或下沉 |
| --- | --- | --- | --- |
| Quick Paste / History | 查找、选择、复用本机内容 | 条目级“发送到设备…”；在线可信设备快捷入口 | 设备列表、协议说明、传输日志 |
| Settings · Local Link | 表达同意与隐私边界 | 总开关、局域网说明、权限状态、“管理设备”入口 | 完整设备卡、配对记录、Transfers |
| Devices | 发现、配对、查看在线状态与撤销 | 本机身份摘要、可信设备、添加设备、重新配对 | 大段协议文案；完整指纹默认折叠 |
| Send | 确认一条文本、目标与当前阶段 | 类型、大小、首行截断、设备、阶段、Cancel | 正文大预览、原始协议状态、旧正文 Retry |
| Incoming | 让接收方决定内容去向 | 无正文通知、元数据、原生按需显示、Copy/Save/Reject | 通知正文、WebView 正文、自动粘贴、隐式保存 |
| Transfers | 回答“发生了什么” | 方向、设备显示名、时间、终态、内容类型/大小区间、诊断编号 | 正文、预览、摘要哈希、来源 App、路径、端点、密钥、Retry |

入口优先级为：条目级“发送到…”、菜单栏 Local Link 状态入口、Settings · Local Link。主工作区
不增加固定设备控制台。

| US-09-02 | 作为配对用户，我想在两台 Mac 上核对同一六位码并由双方确认，从而建立可信连接。 | 60 秒窗口；同一 SAS、固定身份、双方确认；取消、超时、不匹配、重放或身份变化不持久化错误信任。 |

## 全局产品规则

1. 一个请求只有一个不可变终态，所有并发动作争夺同一个原子决策权。
2. 双方状态来自同一 Receipt 映射，不允许一方 Copied、另一方 Expired。
3. 不使用笼统的 “Delivered”。只有经过认证的终态 Receipt 或幂等查询才能证明接收动作。
4. 失败文案必须包含原因、是否送达和下一步；工程状态码不直接进入主要文案。
5. Copy 只写系统剪贴板；Save 只写本机 History；Reject 两者都不写。
6. 通知、Transfers、日志和诊断均不展示正文、首行、摘要哈希或来源 App。
7. 状态必须使用文字和图标，不只依赖颜色；全部主路径可用键盘和 VoiceOver 完成。
8. Local Link 错误不占据 History 主页面，不改变 Enter、复制、搜索、排序、保留和删除语义。

## 产品成功标准

- 双真机首配 50 次，成功率高于 98%，且错误信任为 0。
- 标准局域网 200/200 文本精确传输，错误设备、损坏、丢失和重复均为 0。
- Copy、Save、Reject 各至少 50 次，错误目的地和重复副作用均为 0。
- 发现 p95 ≤ 5 秒；发送到接收卡 p50 ≤ 2 秒、p95 ≤ 5 秒。
- Wi-Fi 切换、AP 隔离、睡眠/唤醒、锁屏、撤销后无旧请求复活。
- 至少 5 名内部参与者可在无指导下完成首次配对和一次发送。
- 所有绝对 No-Go 为 0，并且证据来自同一签名候选 SHA。
